# 2026-05-31 — Phase 1 wrapped

Phase 1 of lawn-agents is feature-complete. Time to step back and write
down what we built, what we left for later, and the handful of things
that surprised me.

## What shipped

The shape we sketched on day one held up — every module that ended up
in `main` is there because we drew it on the whiteboard during the
kickoff session ([2026-05-22 journal](2026-05-22-kickoff.md)). What
changed during build was tactical, not strategic.

The whole pipeline:

1. **`main.py`** parses `--ask` / `--scheduled` / `--plan-month` /
   `--plan-year`, loads `Settings`, and dispatches.
2. **`orchestrator.py`** classifies intent via a `ChatModel` (router),
   fan-outs to the data-source agents, retrieves passages from the
   local RAG, calls the synthesizer with `response_model=Recommendation`,
   re-prompts on Pydantic validation failure, refuses on the second
   failure. Never fabricates.
3. **Data-source agents** — each fails-closed to `None` so a flaky
   endpoint can't kill the run:
   - `agents/weather.py` (NWS api.weather.gov) — 7-day forecast,
     daily highs/lows/precip-chance/max-wind, current temp, 24h +
     7d precip totals, frost-risk flag.
   - `agents/soiltemp.py` (USDA-NRCS AWDB / SCAN) — 2"/4" soil
     temperature + moisture from the nearest SCAN station via
     haversine, with the Parton/Logan modeled fallback deliberately
     deferred (ADR 0004 notes the trigger).
   - `agents/drought.py` (US Drought Monitor REST) — current D-level
     for the configured county FIPS. NOAA CPC seasonal outlooks
     deferred.
   - `agents/knowledge.py` (LanceDB + `BAAI/bge-small-en-v1.5`) —
     vector retrieval with content-addressed chunk IDs so re-ingest
     dedupes. Pluggable `Embeddings` + `VectorStore` Protocols.
   - `agents/research.py` (DuckDuckGo via `ddgs`, allowlisted host
     matching, trafilatura main-content extraction) — fires only on
     weak local retrieval and only when `config.research.enabled`.
4. **`planner.py`** does forward-looking month / year planning,
   reusing the orchestrator's condition-fetch helpers and a
   specialized `prompts/planner.md`.
5. **`notify.py`** renders `Recommendation` via `rich` — green
   headline panel, conditions line, action sections, numbered Sources
   block dedup'd across CalendarItems, refusal panel in red.
6. **`ingest.py`** + `scripts/ingest_corpus.py` populate the RAG from
   `data/corpus/*.pdf` and `seed_urls:` in `config.yaml`. Paragraph-
   aware splitter with overlap; deterministic SHA-256 chunk IDs.
7. **launchd plist** at `scripts/launchd/`. Weekly Monday 7am.
   KeepAlive on non-zero exit with a 10-minute throttle so a
   transient NWS hiccup doesn't spiral.

The provider layer (`llm.py`) sits behind a two-method `ChatModel`
Protocol. Default is Gemini 2.5 Flash (router) + Gemini 2.5 Pro
(synthesizer). One config line away from Anthropic.

## What surprised me

- **The Charleston D3 reality check.** When I first probed the USDM
  API in PR E I assumed "we're in a drought" was background context.
  The live response was D3 — extreme. That's the difference between
  "be a bit cautious" and "defer N entirely." Made every downstream
  prompt + acceptance test more concrete.
- **Tooling chain interactions.** The Python 3.14 vs `google-genai`
  vs strict `filterwarnings = ["error"]` triple cost us a CI fix —
  not a real bug, but a real lesson that "I ran the linter" is not
  the same as "I ran the gates CI runs." `make check` is the cure.
- **Sonar's cognitive-complexity rule is well-calibrated.** Both
  times it fired (PR #12 weather forecast parser, PR #22 soil parser)
  the refactor it forced was a genuine improvement. Worth keeping in
  the gate even when the test-passes-as-is impulse is loud.

## What got deferred

Not technical debt, just things we consciously moved out of Phase 1:

- **Parton/Logan soil-temp model.** Only fires when no SCAN station
  is within radius. Coastal SC has Youmans Farm ~75 mi away so we
  don't need it today. ADR 0004 documents the trigger.
- **NOAA CPC seasonal outlooks.** Point queries against CPC require
  shapefile lookups. Annual planner is good without them — current
  D-level + RAG-derived norms give enough signal.
- **`review-additions` CLI.** The research subagent stores chunks
  with `requires_review=True` but the promote/reject UI is a Phase 2
  task. Synthesizer prompts already label these `[unreviewed]` so the
  human-in-the-loop is preserved.
- **Email / SMS sinks.** `notify.py` ships the `Sink` Protocol; the
  console impl is the only one wired. Adding email is a one-class
  change behind the Protocol.
- **A real LLM acceptance run** for the user's two scenarios
  (peak-by-July-13 plan + GrubX timing). Integration tests (PR H) ran
  the wiring through `FakeChatModel`. Validating actual LLM judgment
  with the populated corpus is the next thing we should do, before
  Phase 2.

## What the blog should say

Three threads worth pulling on when this becomes a post:

1. **Picking the abstraction line for the LLM.** The two-method
   `ChatModel` Protocol is the most important piece of code in the
   repo. Every other decision was less load-bearing. Worth a deep
   dive on why two methods and not three or seven.
2. **The never-guess guardrail as a structural property.** Three
   concentric defenses — prompt, schema, tests — and none of them
   alone would suffice. Walks well as a case study on safety through
   structure rather than through "instruct harder."
3. **The "real data" tax.** I had to actually probe USDM, NWS,
   AWDB to know what their responses looked like. Every protocol
   doc lies about something. Worth showing how each probe became a
   concrete fixture in a test.
